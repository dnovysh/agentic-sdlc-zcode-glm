# Приложение Б. Справочник по конфигурации ZCode 4.0

Это приложение — краткая шпаргалка по тому, где что лежит и как оформляется. Она нужна, когда вы настраиваете репозиторий по главам книги и не хочется листать назад. Все сведения взяты из официальной документации ZCode на выпуск 4.0.0.

## Файлы и папки

| Ресурс | Уровень User | Уровень Project | Глава |
|---|---|---|---|
| Инструкции | `~/.zcode/AGENTS.md` | `AGENTS.md` в корне проекта | 4 |
| Скиллы | `~/.zcode/skills/<имя>/SKILL.md` | `<проект>/.zcode/skills/<имя>/SKILL.md`, также `.agents/skills` | 5 |
| Команды | `~/.zcode/commands/<имя>.md` | папка команд внутри проекта | 5 |
| Субагенты | `~/.zcode/agents/<имя>.md` | `<проект>/.zcode/agents/<имя>.md` | 9 |
| Хуки | `~/.zcode/cli/config.json`, ключ `hooks` | `<проект>/.zcode/config.json` или `zcode.json` | 7 |
| MCP-серверы | `~/.zcode/cli/config.json`, ключ `mcp.servers` | `<проект>/.zcode/config.json`, также `.agents/mcp.json` | 3 |
| Рабочие процессы | `~/.zcode/workflows/<имя>.dwf.ts` | `<проект>/.zcode/workflows/<имя>.dwf.ts` | 11 |
| Память | `~/.zcode/cli/memories/projects/<проект>/memory/` | Нет, только локально | 4 |

Таблица: Где хранятся ресурсы ZCode.

Обратите внимание на разницу уровней. Пользовательский файл конфигурации лежит в `.zcode/cli/`, а файл проекта — прямо в `.zcode/`. Оба называются `config.json`.

Два правила действуют для всего списка.

- **Хуки и MCP-серверы из проекта требуют доверия.** Они не работают, пока вы не нажмёте Trust в настройках. После изменения конфигурации доверие подтверждается заново.
- **Изменения читаются при старте задачи.** После правки начните новую задачу или отправьте `/reload`.

## Скилл

Папка с именем скилла, внутри `SKILL.md`. Имя — строчные буквы, цифры и дефисы.

```markdown
---
name: release-notes
description: >
  Собирает заметки о релизе по мерж-реквестам. Применяй, когда просят
  «написать релиз-ноты» или «что вошло в релиз».
when_to_use: Перед выпуском новой версии
license: MIT
---

# Заметки о релизе

1. Собери влитые мерж-реквесты с прошлого тега: `glab mr list --merged`.
2. Сгруппируй по смыслу: новое, изменено, исправлено.
3. Оформи по шаблону из templates/release.md.
```

Обязательны `name` и `description`. Описание — до 1024 символов, главные слова в начале. Рядом с файлом можно держать `scripts/`, `references/` и `templates/`, ссылаясь на них относительным путём.

## Команда

Один файл `.md` с шапкой и промптом.

```markdown
---
description: Собрать заметки о релизе
argument-hint: "[номер релиза]"
skills: release-notes
---

Используй скилл release-notes и собери заметки для релиза $ARGUMENTS.
```

В промпте доступны `$ARGUMENTS` — весь текст после имени команды, и `$1`, `$2` — отдельные слова. В шапке распознаются `description`, `argument-hint`, `allowed-tools`, `model`, `skills` и `disable-noninteractive`.

## Субагент

Файл `<имя>.md`: шапка с полями, ниже системный промпт.

```markdown
---
name: doc-writer
description: Пишет и правит документацию в docs/ по правилам проекта.
model: GLM-5.3-Flash
thoughtLevel: max
tools: Read, Glob, Grep, Write
maxTurns: 60
background: true
injectAgentsMd: true
---

Ты — технический писатель. Работаешь только с файлами в docs/.
```

| Поле | Что задаёт |
|---|---|
| `model`, `thoughtLevel` | Конкретная модель и уровень рассуждений; без них наследуются у основного агента |
| `tools`, `disallowedTools` | Разрешённые и запрещённые инструменты |
| `maxTurns` | Лимит шагов на один вызов |
| `background` | Разрешение запускать субагента в фоне |
| `injectAgentsMd` | Подставлять ли `AGENTS.md`, по умолчанию да |
| `mcpServers` | MCP-серверы, без которых вызов считается ошибкой |

## Хук

Хуки настраиваются в Settings → Hooks или в файле конфигурации. В файле обязательны ключ `enabled` со значением `true` и секция `events`.

```json
{
  "hooks": {
    "enabled": true,
    "timeoutMs": 60000,
    "maxOutputBytes": 32768,
    "events": {
      "PreToolUse": [
        {
          "matcher": "Edit|Write",
          "hooks": [
            { "type": "process", "command": "node",
              "args": ["scripts/hooks/guard.mjs"] }
          ]
        }
      ]
    }
  }
}
```

| Событие | Что хук читает на входе | Что может ответить |
|---|---|---|
| `SessionStart` | Источник запуска задачи | Текст агенту |
| `UserPromptSubmit` | Текст запроса | Текст агенту или блокировка запроса |
| `PreToolUse` | Инструмент и его аргументы | Разрешить, спросить, запретить, заменить аргументы |
| `PermissionRequest` | Инструмент и аргументы | Разрешить или запретить без вопроса к вам |
| `PostToolUse` | Результат инструмента | Текст агенту |
| `PostToolUseFailure` | Текст ошибки | Подсказку по восстановлению |
| `Stop` | Последнее сообщение модели | Требование продолжить, до трёх раз подряд |

Таблица: События хуков и их возможности.

Ответ пишется в стандартный вывод как JSON внутри объекта `hookSpecificOutput` с полем `hookEventName`. Код выхода `0` — успех, `2` — блокировка, любой другой — ошибка самого хука. Отладочные сообщения пишите в стандартный поток ошибок.

Два способа запуска: `process` выполняет программу с аргументами без оболочки и рекомендуется для всех систем, `command` передаёт строку системной оболочке. По умолчанию хуку даётся 60 секунд.

| Тип | Обязательные поля | Необязательные поля |
|---|---|---|
| `stdio` | `command` | `args`, `cwd`, `env`, `enabled`, `timeoutMs` |
| `http` и `sse` | `url` | `headers`, `enabled`, `timeoutMs` |

Таблица: Поля конфигурации MCP-сервера.

Внутри одного уровня конфигурация `.zcode` важнее файла `.agents/mcp.json`: если в `.zcode` есть хотя бы один сервер, `.agents` игнорируется. При совпадении имён серверов используется сервер проекта.

## Знаки, команды и клавиши

| Элемент | Что делает |
|---|---|
| `$имя` | Вызывает скилл по имени |
| `/` | Открывает команды, скиллы и субагентов |
| `@` | Ссылается на файл, папку, плагин или прошлую задачу |
| `+` | Прикрепляет файлы и документы |
| `/goal` | Показывает, ставит и управляет целью задачи |
| `/compact` | Сжимает контекст, сохраняя главное |
| `/plan` | Включает режим плана |
| `/reload` | Перечитывает конфигурацию в открытой задаче |
| `/side`, `/btw` | Открывают побочную беседу, не прерывая основную |
| `/workflow` | Запускает динамический рабочий процесс |
| `/site-deploy` | Выкладывает прототип в ZCode Sites |
| `Ctrl + Shift + M` | Переключает режим выполнения |
| `Ctrl + T` | Переключает уровень рассуждений |
