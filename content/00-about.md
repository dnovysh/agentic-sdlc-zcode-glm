# Об этой книге

## Кому она адресована

Эта книга для разработчиков, тимлидов и инженеров инфраструктуры, которые пишут код вместе с агентом в ZCode на моделях GLM 5.x и хотят, чтобы этот код можно было спокойно отправлять в продакшен. Она пригодится и тем, кто уже пробовал агентов и разочаровался: агент писал много, быстро и не так, как принято в команде.

Здесь собран порядок действий, который превращает обычный репозиторий в среду, где агент работает уверенно: знает команды сборки и тестов, видит договорённости команды, проверяет себя сам и упирается в запреты там, где решение остаётся за человеком.

## Как устроена книга

Главы идут от простого к сложному, и каждую можно прочитать отдельно.

- Главы 1–2 объясняют, почему агент ошибается и из чего складывается результат: модель, обвязка, репозиторий.
- Главы 3–5 описывают, что агент должен знать и уметь: доступ к сервисам через MCP, инструкции в `AGENTS.md`, скиллы и команды.
- Главы 6–7 показывают, как агент видит результат своей работы и находит свои ошибки: запуск проекта, браузер, тесты, линтеры, хуки.
- Главы 8–9 закрывают путь до основной ветки: обязательные проверки в CI и код-ревью силами субагентов.
- Глава 10 посвящена безопасности: что агент может сломать и какие настройки его останавливают.
- Глава 11 собирает всё в рабочий процесс: маленькие и большие задачи, субагенты, метрики, работа без человека.

Каждая глава заканчивается разделом «С чего начать сегодня» с конкретными шагами и разделом «Проверка» с критериями того, что всё получилось. Приложения содержат адаптацию для Windows и PowerShell, справочник по конфигурации ZCode и указатель промптов.

## Обозначения

| Элемент | Смысл |
|---|---|
| Блок «ПРОМПТ» | Готовый текст для поля ввода агента. Копируется целиком |
| Блок с подписью Bash или PowerShell | Команда для одной из систем. Если команды совпадают, блок один |
| Врезка «Важно» | Утверждение, ошибка в котором обходится дорого |
| Врезка «Совет» | Приём, который экономит время |
| Врезка «Проверка» | Как убедиться, что настройка сработала |
| Врезка «Осторожно» | Действие, которое может что-то сломать |

Команды даются в двух видах. Первый — для Bash: Linux, macOS и Git Bash в Windows. Второй — для PowerShell 7 в Windows. Причины объяснены в приложении А: сам агент в ZCode выполняет команды в Git Bash, поэтому командам для PowerShell там нужен явный вызов `pwsh`.

В тексте используются термины «мерж-реквест» (Merge Request, MR) и «основная ветка». Примеры ориентированы на GitLab; для GitHub отличия указываются по ходу.

## Что проверено, а что нет

Книга опирается на официальную документацию ZCode на сайте [zcode.z.ai](https://zcode.z.ai/en/docs/welcome), документацию моделей на [docs.z.ai](https://docs.z.ai/guides/llm/glm-5.4) и на код открытого репозитория [zai-org/ZCode](https://github.com/zai-org/ZCode). Факты сверены по состоянию на выпуск ZCode 4.0.0 от 23 ноября 2026 года.

Документация меняется быстрее, чем книга. Поэтому для каждой настройки указано, где она находится, чтобы её можно было найти и в новой версии. Всё, что в документации не описано, помечено словами «по коду ZCode» или «проверьте в своей версии».

Два вопроса остались без точного ответа. Z.ai не публикует цену вызова GLM-5.4 через API. И не публикует данных о том, во сколько раз русский текст дороже английского в токенах GLM. В книге эти темы обходятся практическими советами, а не оценками.

## Что понадобится

- ZCode 4.0 или новее и аккаунт с тарифом Coding Plan: на нём доступны GLM-5.4, GLM-5.3 и GLM-5.3-Flash.
- Репозиторий, с которым не страшно экспериментировать. Все проверки из книги лучше сначала провести в отдельной ветке.
- Консольная утилита `glab`, если вы работаете с GitLab. Она нужна в главах 4, 6, 8 и 11.
- PowerShell 7, если вы на Windows. Windows PowerShell 5.1 тоже подойдёт для большинства команд, но в книге используется `pwsh`.

> Совет. Не пытайтесь внедрить всё сразу. Выберите одну главу, сделайте шаги из раздела «С чего начать сегодня», проверьте результат и переходите дальше. Порядок глав подобран так, что каждая следующая опирается на предыдущую.
